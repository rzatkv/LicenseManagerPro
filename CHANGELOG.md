## v3.0.6 — 2026-11-27

Fix round for the dropdown and documentation defects the user reported from his own phone, plus the follow-ups he added the same morning (collapsible widgets, a rational menu, a duplicates sweep and a full security audit):

- **Dropdowns fixed — three real bugs, all root-caused by measuring:** (1) every scrollable dropdown closed the moment the user scrolled its own option list — `TabDropdown` closed on *any* captured scroll event, including scrolls originating inside the list itself, so lower options (ApiDocs verify languages, guide languages, webhook languages, the 33-section Languages editor list) could never be reached, let alone picked. Scrolls inside the list no longer close it; scrolls anywhere else still do. (2) Pressing Escape inside a dropdown that sat in a modal closed the modal underneath it as well — the modal's Escape handler and the dropdown's both fired, detaching the dropdown mid-click. The modal now yields while any dropdown is open (topmost layer wins); the next Escape closes the modal. (3) The same double-dismiss via pointer: a backdrop click while a dropdown was open closed the dropdown AND the modal underneath it — the dropdowns dismiss on document `mousedown`, which fires after the backdrop handler in the bubble path, so the backdrop now dismisses on `mousedown` (where an open dropdown is still visible to the guard) and yields while one is open; the next backdrop press closes the modal. The dismiss logic itself was merged into one shared `useDismiss` hook (see below), so the layering rule lives in one place. Every dropdown in the app was audited in the real demo build (11 TabDropdowns, LanguageMenu, ProfileMenu, bell, GlobalSearch, ThemeToggle — 360px + 1280px, en + fa, light + dark): the three above were the only broken ones.
- **API Docs code boxes grow to fit:** every DocsSample box used to be a fixed-height block with its own inner scrollbar (a 27-line sample measured 118px tall with 652px of content). Every code box in the app now sizes its vertical height to its content — the page scrolls, the box itself never does — and the copy button stays visible on the taller boxes. Checked all 12 ApiDocs samples plus every other `pre` in the app; only the ApiDocs rule had an inner scroll.
- **Menus are readable now — no more see-through dropdowns:** every floating surface (ProfileMenu, LanguageMenu, bell panel, GlobalSearch, gear/visibility popup, details + confirm modals, toasts, the sticky topbar/sidebar and the mobile bottom nav) used the same `--glass` at 0.72 alpha, and over the bright gradient summary cards the page text bled straight through the menu text — the ProfileMenu showed the "Customize" button and "Inactive Licenses" ghosting behind "Profile"/"Settings", in light and dark. Menus now use a dedicated `--glass-menu` at 0.97 alpha with the same 24px blur, glass border and shadow, so the frosted-glass look survives but no page text shows through (0.94 still left a faint ghost over the highest-contrast cards, measured in Playwright screenshots). Page surfaces (cards, tables, containers) keep 0.72 — they sit on the plain page background, not over text. Every surface was measured open over real content at 360px + 1280px, en + fa, light + dark (32 measurements; TabDropdown was already solid and is the control).
- **Collapsible dashboard widgets:** every one of the 8 chart widgets now has a collapse/expand chevron in its header (the Services widget too, next to its re-check button). Collapsed, only the slim header row shows; expanded, the chart, its type switcher and its size/reorder controls are all back. The collapsed state persists per admin exactly like the rest of the dashboard personalization (localStorage + `PUT /users/me/preferences`) and survives a real reload; collapsing never leaves empty gaps or overflows at 360px. Sections were deliberately left without collapse — they already have visibility toggles, and the user asked for widgets.
- **Menus regrouped, strictly by what each item is:** Downloads and Notifications both sat under Management, which neither of them is. The sidebar is now Overview (Dashboard, Notifications, Activity History, About — the read-only monitoring/info pages), Licenses (Licenses, Products, Product Groups — unchanged), Access (API Keys, Users, Roles, Blacklist — unchanged), Resources (Downloads, API Docs — the things you take from the panel to integrate with it), and Settings as a top-level link (one configuration area is not a group of one). Routes, accordion behaviour, the active-group-open rule and the phone drawer are unchanged.
- **Duplicates removed:** the outside-click + Escape dismiss logic existed in 6 copies (now one `useDismiss` hook, 7 call sites — which also gave ConfirmModal a missing Escape handler for free), the five `api.js` request wrappers are one shared `request()`, and the ~20 hand-rolled page fetch blocks are one `useListFetch` hook (11 list pages migrated; the hook also fixed a double-fetch in Blacklist). 52 dead i18n keys deleted (906/906 parity kept). ConfirmModal is now a thin wrapper over Modal (same props, 10 call sites untouched). The demo module copy now matches `modules.json` verbatim for all 10 modules (7 had drifted). A new backend contract test (`backend/tests/test_demo_contract.py`, 14 tests) pins the parallel lists that must not drift again — permissions, roles, settings keys, SMS providers, themes, billing cycles, audit channels, module manifests and versions. Deliberately NOT merged, with the reason recorded: the OpenCart admin/catalog models (no PHP runtime here to verify a merge), the per-platform module code (each ships as a standalone ZIP), and the near-identical CSS class names in several files (same-name rules that rely on load order — moving them needs per-page visual verification).
- **Security audit — every bug found is patched:** (1) LOW — an internal error leaked to clients: the update-check `error` field and the apply-update 400 detail echoed the raw exception text (`str(exc)`), so a server-side failure (proven in the test run: a `NameError` naming an internal symbol) was returned verbatim. The detail now stays in the server log; callers get the generic "GitHub update check failed". Regression test `test_update_check_exception_leaks_nothing` fails on the old code and passes on the new. (2) The demo mock routed bare paths but compared the raw `/api/...` path, so `GET /api/captcha/config` 404'd on every login-page load — fixed by normalising the path once (`barePath`), with two new check-demo assertions. (3) The version bump had missed one rename (`RELEASE_306` in the update tests) — fixed, it was the cause of 3 failing tests. Audited clean with no change needed: no XSS surface (`dangerouslySetInnerHTML`/innerHTML/eval absent), only constant SQL strings, list-form subprocess only, allowlisted module ids and double-validated tarball members (no traversal/Zip-Slip), a webhook SSRF guard that resolves the host and blocks private/loopback/link-local ranges, bcrypt + signed short-lived 2FA temp tokens + TOTP replay protection, a rate-limited public license check with blacklist and locks enforced, SHA-256-hashed module keys with expiry/IP allowlist/HMAC/replay cache, every endpoint authenticated except the intentionally public news/captcha/validate/auth routes, no file-upload endpoint at all, and security headers + API CSP + localhost-only CORS. The deeper audit found and patched more, each with a test that fails before the fix and passes after: (H1, HIGH) a 2FA temp token could create an admin via `POST /api/auth/register` — the optional-auth helper verified the token but never checked its purpose, so a stolen password alone defeated the second factor; purpose tokens are now rejected there and in the maintenance bypass. (H2, HIGH) the public license check trusted the caller-supplied `ip`, so a locked license validated from anywhere by sending the locked IP; the route now uses the observed connection IP. (H3, HIGH) the app booted with the publicly known default JWT secret — it now refuses to start unless `LMP_ALLOW_DEFAULT_SECRET=1` is set for local dev, and compose requires `SECRET_KEY` to be set. (H4, HIGH) compose shipped default DB passwords and published MySQL on 3306 — defaults removed (`${VAR:?…}`), MySQL bound to 127.0.0.1. (M1) validate failed forever once `max_activations` was reached, even for the legitimately activated machine — the limit is now enforced only at activation time, where the fingerprint is known. (M2) the public validate endpoint returned the full license record (owner email, notes, lock lists, install path) — it now returns only the 7 fields modules actually use. (M3) any manager could send an arbitrary SMS to any number via the test endpoint — admin-only now. (M4) the updater fetched any tarball host and `update.sh` let hard links and setuid bits through — GitHub hosts only, `h` added to the tar type class, `--no-same-owner/--no-same-permissions`, mode-stripping copy, setuid/setgid stripped after the copy. (M6) TOTP verify had no per-account attempt cap — failed attempts now feed the 5-in-15-min lockout. (M7) the demo mock (demo users, demo API keys, demo 2FA code) was statically bundled into every production build — it is now a lazy `import()` chunk; the production main bundle contains none of `DEMO2FASECRET`/`lmp_demo_`/`lmp-demo-db` (verified by rebuilding with `DEMO_MODE=false` and grepping; the demo login still works through the chunk). Lows fixed: HSTS header (backend + nginx vhosts), 2FA codes from `secrets` instead of `random`, captcha challenge pruning + 10/min rate limit, generic error details on `/ready` and the service-status checks (details stay in the log), news links rendered only for http(s), install.sh no longer accepts passwords on the command line (env vars or hidden prompt only), the maintenance bypass now checks the `*` permission instead of the role string, `dashboard:read` granted to manager/support/viewer (it existed in no role's set, so every non-admin got 403 on the dashboard), passwords over 72 bytes rejected (bcrypt truncates silently past 72), and uvicorn runs with `--proxy-headers --forwarded-allow-ips=127.0.0.1` so rate limits and IP allowlists see the real client behind nginx. Explicitly NOT fixed this round, with the reason recorded in the v3.0.6 report: at-rest encryption of stored secrets (needs a Fernet key + migration), JWT revocation (needs a `token_version` migration), a change-password endpoint (a feature, not a patch), narrowing the frontend CSP `connect-src` (the API origin is not known at build time), the per-process HMAC replay cache (single-worker default — documented), and whether viewer/support may enumerate all license keys (a product decision for the owner). `pip-audit`: no known vulnerabilities. `npm audit` could not run in this environment (the VM egress policy blocks the registry audit endpoint) — recorded, not skipped silently.

### Production checklist

Before running the API in production: (1) set a long random `SECRET_KEY` in `.env` (the app logs a warning at startup if the shipped default is still in use); (2) set `CORS_ORIGINS` explicitly to your frontend origin(s); (3) use MySQL (`DATABASE_URL=mysql+pymysql://...`) instead of SQLite; (4) run `POST /api/system/check-expiring?days=7` from cron daily so expiry webhooks fire; (5) back up the database regularly; (6) put the API behind HTTPS (e.g. Nginx as a reverse proxy); (7) tune the rate limits (`RATE_LIMIT_AUTH_PER_MINUTE`, `RATE_LIMIT_VALIDATE_PER_MINUTE`) for your traffic.
